LDSO-Entities: Named Entity Reference Module

LDSO-Entities (v1.0.0) is a lightweight RDF/OWL vocabulary for classifying and linking named real-world entities referenced within legal documents — persons, organizations, locations, legal concepts, roles, events, and processes. Entity types are expressed as SKOS concepts in a controlled vocabulary (ent:EntityTypeScheme), not as OWL subclasses, enabling flat, open-ended, multi-dimensional classification that domain verticals can extend without modifying this ontology.

Document-level annotation (entity mentions, surface forms, character offsets, NER confidence) is defined in LDSO-Annotations. Definitional content (what a concept means) belongs to LDSO-Semantics.

Introduction

Legal documents are rich in references to named real-world entities: the World Customs Organization, a contracting party, a geographic territory, a legal concept such as "temporary admission", or an administrative event such as "entry into force". These entities are structural anchors — they appear repeatedly across provisions, across documents, and across jurisdictions.

LDSO-Entities provides a thin but precisely typed catalogue layer. Its design principles are:

  1. Single OWL class, open SKOS taxonomy. All entities are instances of ent:NamedEntity. Entity type is expressed via ent:entityType pointing to SKOS concepts, not via OWL subclasses. This allows multi-dimensional classification (an entity is both an Organization and a trade:IGO) and open-ended extension without subclassing.
  2. IRI-first identity. Every entity carries a canonical ent:href URI pointing to an authoritative external register (GeoNames, Wikidata, national registers) or a project-internal IRI scheme.
  3. Multilingual display. Every entity carries one or more ent:showAs values, language-tagged, as the entity appears in the source text.
  4. Layer separation. LDSO-Entities contains only the entity catalogue — that the entity exists and what URI identifies it. Document annotation (linking elements to entities) belongs to LDSO-Annotations. Definitional content belongs to LDSO-Semantics.

Classes

ent:NamedEntity

IRIhttps://w3id.org/ldso/entities#NamedEntity
LabelNamed Entity
DefinitionA named, referenceable real-world entity that is mentioned or invoked within a legal document — a person, organization, place, concept, role, event, or process. Named entities are identified by a canonical URI (ent:href) and carry a display form (ent:showAs) as they appear in the source text.
UsageEvery instance MUST carry ent:href, ent:showAs, and at least one ent:entityType pointing to a concept from ent:EntityTypeScheme. Do NOT use OWL subclasses to type entities — always use a ent:NamedEntity ; ent:entityType ent:Organization rather than a ent:Organization.
Entity typesExpressed via ent:entityType pointing to SKOS concepts in ent:EntityTypeScheme — see below.

Conformance

A conforming LDSO-Entities implementation MUST:

  1. Type every entity catalogue node as ent:NamedEntity.
  2. Express entity type classification via ent:entityType pointing to one or more skos:Concept instances in ent:EntityTypeScheme or a compatible extension scheme. OWL subclassing of ent:NamedEntity MUST NOT be used to express entity type.
  3. Assign each ent:NamedEntity at least one ent:showAs value (language-tagged) and one ent:href value (absolute URI pointing to an authoritative external register or project IRI).
  4. Use only IRIs for entity identity — blank nodes MUST NOT be used as ent:NamedEntity instances.
  5. Pass all SHACL shapes defined in shapes.ttl without violations.

A conforming implementation SHOULD:

  • Link ent:NamedEntity IRIs to authoritative external registers (Wikidata, GeoNames, national authority files) via ent:href.
  • Assign entity type concepts that are skos:topConceptOf ent:EntityTypeScheme or skos:narrower descendants thereof.

Entity Type Vocabulary (SKOS)

ent:EntityTypeScheme is a [[SKOS]] ConceptScheme defining seven top-level entity type concepts. Entity types are assigned via ent:entityType on a ent:NamedEntity instance — not by OWL subclassing. Multiple ent:entityType assertions are permitted and expected for multi-dimensional classification.

Concept IRILabelDefinitionExamples
ent:Person Person A named natural person referenced in a legal document. Signatories, individual parties, authors
ent:Organization Organization A named legal person, governmental body, intergovernmental organization, or collective body. Governments, international organizations, courts, standards bodies, treaty parties
ent:Location Location A named geographic or jurisdictional location referenced in a legal document. Countries, territories, customs zones, ports, designated areas
ent:Concept Concept A named legal concept or term of art referenced in a legal document. "originating goods", "temporary admission", "customs duty", "ATA carnet"
ent:Role Role A named legal or institutional role referenced in a legal document. "customs officer", "competent authority", "importer of record"
ent:Event Event A named legal or historical event referenced in a legal document. "entry into force", "ratification", "signing ceremony", "accession"
ent:Process Process A named legal or administrative process referenced in a legal document. "customs clearance", "dispute settlement", "legislative procedure"

Domain verticals extend the vocabulary by declaring skos:Concept instances with skos:broader pointing to one of these seven primaries — no subclassing required: 

trade:CustomsAdministration
  a skos:Concept ;
  skos:broader ent:Organization ;
  skos:inScheme trade:TradeEntityTypeScheme ;
  rdfs:label "Customs Administration"@en .

# Assign multi-dimensional type to an entity
ex:canada_cbsa
  a ent:NamedEntity ;
  ent:entityType ent:Organization ;           # primary: from core scheme
  ent:entityType trade:CustomsAdministration ; # secondary: from trade scheme
  ent:href "https://www.cbsa-asfc.gc.ca"^^xsd:anyURI ;
  ent:showAs "Canada Border Services Agency"@en ;
  rdfs:label "Canada Border Services Agency"@en .

Properties

Object Properties

ent:entityType

IRIhttps://w3id.org/ldso/entities#entityType
Labelentity type
DefinitionClassifies a NamedEntity along one or more dimensions using SKOS concepts. At least one concept from ent:EntityTypeScheme SHOULD be present to identify the primary category.
Rangeskos:Concept
UsageMultiple ent:entityType assertions are permitted and expected for multi-dimensional classification. One assertion MUST reference a top-level concept from ent:EntityTypeScheme (primary category); additional assertions may reference narrower concepts from domain-specific ConceptSchemes (secondary dimensions).
 
ex:wco
  a ent:NamedEntity ;
  ent:entityType ent:Organization ;           # primary category (core scheme)
  ent:entityType trade:IntergoverOrg .        # secondary category (trade scheme)

Datatype Properties

PropertyLabelRangeCardinalityDefinition
ent:href href xsd:anyURI exactly 1 The canonical URI identifying a named entity. Use a persistent, resolvable URI from an authoritative register (GeoNames, Wikidata, national registers).
ent:showAs show as rdf:langString at least 1 The human-readable display form of a named entity, as it appears in the source legal text. Assert with a BCP 47 language tag. Multiple values for different language versions are permitted.

Entity Annotation (LDSO-Annotations)

Linking document elements to named entities, and recording surface forms with character offsets, is handled by the LDSO-Annotations module, not by LDSO-Entities. The two relevant patterns are: 

@prefix ann: <https://w3id.org/ldso/annotations#> .

ex:art_5
  ann:refersToEntity ex:temporary_admission ;
  ann:refersToEntity ex:competent_authority .
ex:mention_1
  a ann:EntityMention ;
  ann:inElement ex:para_2 ;
  ann:refersToEntity ex:wco ;
  ann:surfaceForm "World Customs Organization"@en ;
  ann:charStart 42 ;
  ann:charEnd 68 ;
  ann:nerConfidence "0.98"^^xsd:decimal .

SHACL Shapes

Validation shapes are defined in shapes.ttl.

ShapeTargetConstraints
ent:NamedEntityShape ent:NamedEntity sh:nodeKind sh:IRI;
rdfs:label minCount 1 (Warning);
ent:href minCount 1, datatype xsd:anyURI (Violation);
ent:showAs minCount 1, datatype rdf:langString (Violation);
ent:entityType minCount 1, class skos:Concept (Violation)
ent:EntityTypePrimaryCategoryShape ent:NamedEntity (SPARQL target) SPARQL: at least one ent:entityType concept exists in ent:EntityTypeScheme (primary category required)
ent:EntityTypeSinglePrimaryShape ent:NamedEntity (SPARQL target) SPARQL: at most one top-level concept from ent:EntityTypeScheme (prevents dual primary classification)
ent:ConceptShowAsShape Entities with ent:entityType ent:Concept (SPARQLTarget) ent:showAs minCount 1, datatype rdf:langString (Violation)
ent:EntityTypeSchemeShape ent:EntityTypeScheme (targetNode) Seven skos:hasTopConcept assertions: Person, Organization, Location, Concept, Role, Event, Process
ent:EntityTypeConceptShape Concepts in ent:EntityTypeScheme (SPARQLTarget) skos:inScheme required; rdfs:label required (Violation)

Usage Patterns

Shared Entity Catalogue

Named entities SHOULD be declared in a shared catalogue graph, separate from individual document graphs. This allows the same entity node (e.g., the World Customs Organization) to be referenced from multiple documents without duplication. Always use a ent:NamedEntity ; ent:entityType ent:Organization — never a ent:Organization. 

@prefix ent:  <https://w3id.org/ldso/entities#> .
@prefix xsd:  <http://www.w3.org/2001/XMLSchema#> .
@prefix ex:   <https://example.org/ata/> .

ex:wco
  a ent:NamedEntity ;
  ent:entityType ent:Organization ;
  ent:href "https://www.wcoomd.org"^^xsd:anyURI ;
  ent:showAs "World Customs Organization"@en ;
  ent:showAs "Organisation mondiale des douanes"@fr ;
  rdfs:label "World Customs Organization"@en .

ex:temporary_admission
  a ent:NamedEntity ;
  ent:entityType ent:Concept ;
  ent:href "https://example.org/legal/concepts/temporary-admission"^^xsd:anyURI ;
  ent:showAs "temporary admission"@en ;
  ent:showAs "admission temporaire"@fr ;
  rdfs:label "temporary admission"@en .

ex:competent_authority
  a ent:NamedEntity ;
  ent:entityType ent:Role ;
  ent:href "https://example.org/roles/competent-authority"^^xsd:anyURI ;
  ent:showAs "competent authority"@en ;
  ent:showAs "autorité compétente"@fr ;
  rdfs:label "competent authority"@en .

Competency Questions

The following questions define what LDSO-Entities is designed to answer. Each is accompanied by a SPARQL query against a conformant dataset.

CQ-E-01 — Which named entities in the catalogue are Organizations?

PREFIX ent:  <https://w3id.org/ldso/entities#>
PREFIX skos: <http://www.w3.org/2004/02/skos/core#>

SELECT ?entity ?showAs ?href WHERE {
  ?entity a ent:NamedEntity ;
          ent:entityType ?type ;
          ent:showAs ?showAs ;
          ent:href ?href .
  { ?type skos:broader* ent:Organization }
  FILTER(LANG(?showAs) = "en")
}
ORDER BY ?showAs

CQ-E-02 — What is the authoritative URI of a given named entity?

PREFIX ent:  <https://w3id.org/ldso/entities#>

SELECT ?href WHERE {
  ?entity ent:showAs "World Customs Organization"@en ;
          ent:href   ?href .
}

CQ-E-03 — Which entities belong to more than one type category?

PREFIX ent:  <https://w3id.org/ldso/entities#>
PREFIX skos: <http://www.w3.org/2004/02/skos/core#>

SELECT ?entity ?showAs (COUNT(DISTINCT ?type) AS ?typeCount) WHERE {
  ?entity a ent:NamedEntity ;
          ent:entityType ?type ;
          ent:showAs ?showAs .
  ?type skos:topConceptOf ent:EntityTypeScheme .
  FILTER(LANG(?showAs) = "en")
}
GROUP BY ?entity ?showAs
HAVING(?typeCount > 1)
ORDER BY DESC(?typeCount)

CQ-E-04 — What display forms are known for a given entity?

PREFIX ent: <https://w3id.org/ldso/entities#>

SELECT ?showAs (LANG(?showAs) AS ?language) WHERE {
  <https://example.org/entity/wco> ent:showAs ?showAs .
}
ORDER BY ?language ?showAs

CQ-E-05 — Which provisions reference a given entity (via LDSO-Annotations)?

PREFIX ldso: <https://w3id.org/ldso/core#>
PREFIX ent:  <https://w3id.org/ldso/entities#>
PREFIX ann:  <https://w3id.org/ldso/annotations#>

SELECT DISTINCT ?element ?citation WHERE {
  ?entity ent:showAs "World Customs Organization"@en .
  ?element ann:refersToEntity ?entity ;
           ldso:citation ?citation .
}
ORDER BY ?citation

CQ-E-06 — Which entities of a given type appear across a chapter?

PREFIX ldso: <https://w3id.org/ldso/core#>
PREFIX ent:  <https://w3id.org/ldso/entities#>
PREFIX ann:  <https://w3id.org/ldso/annotations#>
PREFIX skos: <http://www.w3.org/2004/02/skos/core#>

SELECT DISTINCT ?entity ?typeConcept ?showAs WHERE {
  ?chapter a ldso:Chapter ;
           ldso:notation "2" ;
           ldso:contains+ ?element .
  ?element ann:refersToEntity ?entity .
  ?entity  ent:entityType ?typeConcept ;
           ent:showAs ?showAs .
  ?typeConcept skos:inScheme ent:EntityTypeScheme .
  FILTER(LANG(?showAs) = "en")
}
ORDER BY ?typeConcept ?showAs
