LDSO-Annotations: Document Annotation Module

LDSO-Annotations is an RDF/OWL vocabulary for annotating legal document elements with references to named entities. It operates at two complementary granularities: a coarse level suitable for human-curated annotation and entity indexing, and a fine level that captures the exact surface form, character offsets, and NER confidence score for each entity occurrence — the primary output unit of NLP parsing pipelines.

This module imports LDSO-Core for document structure and LDSO-Entities for the canonical entity catalogue. It sits above both in the LDSO module stack as Layer 2c.

Introduction

Legal documents contain numerous references to named real-world entities: international organizations, geographic territories, legal concepts, administrative roles, events, and processes. Two distinct use cases arise when linking document content to those entities:

  1. Coarse annotation — A curator reads an article and marks which entities it mentions, without recording which exact phrases triggered that judgment or where in the text they appear. This is sufficient for entity indexing and document retrieval.
  2. Fine annotation — An NLP pipeline identifies each entity occurrence in the text, records the exact surface form as it appears (which may differ from the canonical display form — "WCO", "the Organization", "World Customs Organization" are all mentions of the same entity), and optionally captures character offsets and a confidence score. This is the primary output of named entity recognition (NER) systems.

LDSO-Annotations supports both use cases through a single vocabulary. The two levels are designed to be complementary: fine-grained mentions can co-exist with coarse references on the same element, enabling the coarse layer to serve as a complete entity index independently of whether NLP output is available.

Design Principles

  1. Separation of catalogue and annotation. The canonical entity catalogue lives in LDSO-Entities. LDSO-Annotations only records linkages between document locations and catalogue entries — it adds no new entity types or entity properties.
  2. One mention node per occurrence. Each distinct occurrence of a named entity in a single document element is represented as a separate ann:EntityMention node. The same canonical entity may appear multiple times in a single paragraph under different surface forms (e.g., "WCO", "the Organization", "World Customs Organization"); each occurrence receives its own mention node.
  3. No rdfs:domain on annotation properties. SHACL shapes in shapes.ttl are the sole validation authority. OWL domain declarations are omitted to prevent unintended inference from polluting graphs that use annotation properties in other contexts.
  4. Language-tagged surface forms. ann:surfaceForm values MUST carry a BCP 47 language tag matching the language of the containing document expression, enabling correct multilingual lookup and comparison.
  5. Offset semantics. ann:startChar and ann:endChar are zero-based, measured against the ldso:text literal of the containing element. The slice text[startChar:endChar] (Python notation) produces the surface form. ann:endChar MUST be strictly greater than ann:startChar and MUST be present whenever ann:startChar is asserted.

Annotation Model

Coarse Annotation

The coarse annotation pattern links a document element directly to a canonical named entity via ann:refersToEntity. It records which entities are mentioned in an element without recording where or how. 

# An article refers to three canonical entities
ex:art_5
  a ldso:Article ;
  ann:refersToEntity ex:temporary_admission,
                     ex:competent_authority,
                     ex:customs_territory .

Use ann:refersToEntity when mention-level granularity is not required — for human-curated annotation at the article or paragraph level, or for simple entity indexing across a document corpus.

Fine Annotation

The fine annotation pattern uses ann:EntityMention nodes to record each individual occurrence of a named entity. Each mention node carries the exact surface form, optional character offsets, and an optional NER confidence score. 

# A paragraph with two entity mentions
ex:para_2
  a ldso:Paragraph ;
  ldso:text "The World Customs Organization (WCO) and the competent authority ..."@en ;
  ann:hasMention ex:m_wco_para2, ex:m_authority_para2 .

# First mention: full name form
ex:m_wco_para2
  a ann:EntityMention ;
  ann:mentionOf   ex:wco ;
  ann:inElement   ex:para_2 ;
  ann:surfaceForm "World Customs Organization"@en ;
  ann:startChar   4 ;
  ann:endChar     32 ;
  ann:confidence  0.98 .

# Second mention: abbreviated form of the same canonical entity
ex:m_wco_abbrev
  a ann:EntityMention ;
  ann:mentionOf   ex:wco ;
  ann:inElement   ex:para_2 ;
  ann:surfaceForm "WCO"@en ;
  ann:startChar   34 ;
  ann:endChar     37 ;
  ann:confidence  0.99 .

# Third mention: different canonical entity
ex:m_authority_para2
  a ann:EntityMention ;
  ann:mentionOf   ex:competent_authority ;
  ann:inElement   ex:para_2 ;
  ann:surfaceForm "competent authority"@en ;
  ann:confidence  0.91 .

Using Both Levels Together

The SHACL shape ann:MentionCoarseConsistencyShape warns when an element carries fine-grained mentions but is missing the corresponding coarse ann:refersToEntity assertions. The recommended pattern is to assert both levels: coarse references for efficient entity indexing and SPARQL lookup, fine mentions for provenance, surface form variants, and span highlighting. 

ex:para_2
  ann:refersToEntity ex:wco, ex:competent_authority ;  # coarse index
  ann:hasMention ex:m_wco_para2, ex:m_wco_abbrev,     # fine provenance
                 ex:m_authority_para2 .

Classes

ann:EntityMention

IRI https://w3id.org/ldso/annotations#EntityMention
Label Entity Mention
Definition A single occurrence of a named entity within a specific location in a legal document. Captures the exact surface form as it appears in the source text, the document element in which it occurs, optional character offsets for span-level highlighting, and an optional NER confidence score.
Usage ann:EntityMention is the primary output unit of NLP/NER parsing pipelines. Each mention node MUST be linked to its canonical ent:NamedEntity via ann:mentionOf and to its containing document element via ann:inElement.

Multiple mentions in the same element are represented as separate ann:EntityMention nodes — one per distinct surface-form occurrence. The same canonical entity may appear multiple times in a single paragraph under different surface forms ("WCO" and "the Organization") — each occurrence is a separate mention.

For coarse annotation without span-level detail, use ann:refersToEntity directly on the document element.
Required properties ann:mentionOf (exactly 1), ann:inElement (exactly 1), ann:surfaceForm (exactly 1)
Optional properties ann:startChar, ann:endChar (both together or neither), ann:confidence
Example 
ex:m_wco_para2
  a ann:EntityMention ;
  ann:mentionOf   ex:wco ;
  ann:inElement   ex:para_2 ;
  ann:surfaceForm "World Customs Organization"@en ;
  ann:startChar   23 ;
  ann:endChar     51 ;
  ann:confidence  0.98 .

Object Properties

ann:refersToEntity

IRI https://w3id.org/ldso/annotations#refersToEntity
Labelrefers to entity
Definition Coarse-grained link from a legal document element to a canonical named entity it mentions somewhere in its text.
Rangeent:NamedEntity
OWL characteristics owl:AsymmetricProperty
Usage Use when mention-level granularity is not required. A single element may carry multiple ann:refersToEntity assertions, one per distinct canonical entity mentioned. For NLP pipeline output with surface form and character offsets, use the fine-grained pattern with ann:EntityMention instead.
Example 
ex:art_5
  ann:refersToEntity ex:temporary_admission,
                     ex:competent_authority .

ann:mentionOf

IRI https://w3id.org/ldso/annotations#mentionOf
Labelmention of
Definition Links an entity mention to the canonical named entity it is an occurrence of.
Rangeent:NamedEntity
OWL characteristics owl:FunctionalProperty — a mention is always an occurrence of exactly one canonical entity.
CardinalityExactly 1 (MUST)
Example 
ex:m_wco_para2  ann:mentionOf  ex:wco .

ann:inElement

IRI https://w3id.org/ldso/annotations#inElement
Labelin element
Definition Links an entity mention to the document element (paragraph, item, article, etc.) in which it occurs.
OWL characteristics owl:FunctionalProperty, owl:AsymmetricProperty, owl:IrreflexiveProperty
Inverseann:hasMention
CardinalityExactly 1 (MUST)
Usage The target is typically an ldso:Paragraph, ldso:Item, or another fine-grained structural element from LDSO-Core. A mention occurs in exactly one document element.
Example 
ex:m_wco_para2  ann:inElement  ex:para_2 .

ann:hasMention

IRI https://w3id.org/ldso/annotations#hasMention
Labelhas mention
Definition Links a document element to an entity mention occurring within it.
Rangeann:EntityMention
OWL characteristics owl:AsymmetricProperty, owl:IrreflexiveProperty
Inverseann:inElement
Usage Navigate from a document element to all entity mentions it contains. An element may carry multiple ann:hasMention assertions — one per distinct occurrence of any entity in its text.
Example 
ex:para_2
  ann:hasMention ex:m_wco_para2, ex:m_authority_para2 .

Datatype Properties

ann:surfaceForm

IRI https://w3id.org/ldso/annotations#surfaceForm
Labelsurface form
Definition The exact textual string of the entity mention as it appears in the source document, with a BCP 47 language tag matching the document language.
Rangerdf:langString
CardinalityExactly 1 (MUST)
Usage Always language-tagged (e.g., "WCO"@en, "OMD"@fr). Distinct from ent:showAs, which carries the canonical preferred display form. ann:surfaceForm records exactly what the parser found — abbreviations, inflected forms, and partial names are all valid.
Example 
ex:m_wco_full   ann:surfaceForm "World Customs Organization"@en .
ex:m_wco_abbrev ann:surfaceForm "WCO"@en .
ex:m_wco_anap   ann:surfaceForm "the Organization"@en .

ann:startChar

IRI https://w3id.org/ldso/annotations#startChar
Labelstart character
Definition Zero-based character offset of the first character of the entity mention span within the plain-text content of its containing element.
Rangexsd:nonNegativeInteger
OWL characteristics owl:FunctionalProperty
CardinalityAt most 1. When present, ann:endChar MUST also be present and strictly greater.
Usage Offsets are relative to the string value of ldso:text on the ann:inElement node (the plain-text content of that structural element). Assert only when character-level span highlighting is required.
Example 
ex:m_wco_para2
  ann:startChar  23 ;
  ann:endChar    51 .

ann:endChar

IRI https://w3id.org/ldso/annotations#endChar
Labelend character
Definition Exclusive character offset of the character immediately following the last character of the entity mention span.
Rangexsd:nonNegativeInteger
OWL characteristics owl:FunctionalProperty
CardinalityAt most 1. MUST be present whenever ann:startChar is asserted. MUST be strictly greater than ann:startChar.
Usage Exclusive upper bound — the mention span is text[startChar:endChar] in Python slice notation. The length of the span is endChar − startChar characters.
Example 
# "World Customs Organization" occupies characters 23–50 (length 28)
ex:m_wco_para2
  ann:startChar  23 ;
  ann:endChar    51 .

ann:confidence

IRI https://w3id.org/ldso/annotations#confidence
Labelconfidence
Definition The NER model confidence score for this entity mention, expressed as a decimal in the range [0.0, 1.0].
Rangexsd:decimal ∈ [0.0, 1.0]
OWL characteristics owl:FunctionalProperty
CardinalityAt most 1 (optional).
Usage Populated by NLP pipelines; omit for human-curated annotations where confidence is implicitly 1.0. A SHACL constraint enforces the [0.0, 1.0] range.
Example 
ex:m_wco_para2  ann:confidence  0.98 .

SHACL Validation Shapes

Validation shapes are defined in shapes.ttl. Run validation with: 

pyshacl -s shapes.ttl -sf turtle -df turtle examples/example.ttl

ann:EntityMentionShape

Targetsh:targetClass ann:EntityMention
Validates
  • ann:mentionOf — exactly 1, pointing to an ent:NamedEntity IRI (Violation)
  • ann:inElement — exactly 1 IRI (Violation)
  • ann:surfaceForm — exactly 1 rdf:langString (Violation)
  • ann:startChar — at most 1 xsd:nonNegativeInteger (Violation)
  • ann:endChar — at most 1 xsd:nonNegativeInteger (Violation)
  • ann:confidence — at most 1 xsd:decimal ∈ [0.0, 1.0] (Violation)

ann:EntityMentionOffsetShape

Targetsh:targetClass ann:EntityMention
Validates Two SPARQL constraints:
  • ann:startChar present but ann:endChar absent — Violation
  • ann:endChar ≤ ann:startChar — Violation

ann:RefersToEntityShape

Target SPARQL target: objects of ann:refersToEntity
Validates Each target SHOULD be typed as ent:NamedEntity (Warning)

ann:MentionCoarseConsistencyShape

Target SPARQL target: elements that carry at least one ann:hasMention
Validates For each entity mentioned via ann:hasMention / ann:mentionOf, the element SHOULD also carry ann:refersToEntity for the same canonical entity (Warning — index completeness)

Competency Questions

The following questions define what LDSO-Annotations is designed to answer. Each is accompanied by a SPARQL query against a conformant dataset.

CQ-A-01 — Which named entities are mentioned in a given article?

PREFIX ann:  <https://w3id.org/ldso/annotations#>
PREFIX ldso: <https://w3id.org/ldso/core#>

SELECT DISTINCT ?entity WHERE {
  <https://example.org/ata/art_5> ldso:contains* ?element .
  ?element ann:refersToEntity ?entity .
}

CQ-A-02 — Where does a named entity appear (element, citation, offsets)?

PREFIX ann:  <https://w3id.org/ldso/annotations#>
PREFIX ent:  <https://w3id.org/ldso/entities#>
PREFIX ldso: <https://w3id.org/ldso/core#>

SELECT ?element ?citation ?surfaceForm ?start ?end WHERE {
  ?entity ent:showAs "World Customs Organization"@en .
  ?element ann:hasMention ?mention ;
           ldso:citation ?citation .
  ?mention ann:mentionOf ?entity ;
           ann:surfaceForm ?surfaceForm .
  OPTIONAL { ?mention ann:startChar ?start ; ann:endChar ?end . }
}
ORDER BY ?citation ?start

CQ-A-03 — What surface form variants appear for a given entity?

PREFIX ann: <https://w3id.org/ldso/annotations#>
PREFIX ent: <https://w3id.org/ldso/entities#>

SELECT DISTINCT ?surfaceForm (COUNT(?m) AS ?occurrences) WHERE {
  ?entity ent:showAs "World Customs Organization"@en .
  ?m ann:mentionOf ?entity ;
     ann:surfaceForm ?surfaceForm .
}
GROUP BY ?surfaceForm
ORDER BY DESC(?occurrences)

CQ-A-04 — Which document elements reference a given entity concept?

PREFIX ann:  <https://w3id.org/ldso/annotations#>
PREFIX ent:  <https://w3id.org/ldso/entities#>
PREFIX ldso: <https://w3id.org/ldso/core#>

SELECT ?element ?citation WHERE {
  ?concept ent:showAs "temporary admission"@en .
  ?element ann:refersToEntity ?concept ;
           ldso:citation ?citation .
}
ORDER BY ?citation

CQ-A-05 — How many times does each entity appear in the document?

PREFIX ann: <https://w3id.org/ldso/annotations#>
PREFIX ent: <https://w3id.org/ldso/entities#>

SELECT ?entity ?showAs (COUNT(?mention) AS ?frequency) WHERE {
  ?mention a ann:EntityMention ;
           ann:mentionOf ?entity .
  ?entity ent:showAs ?showAs .
  FILTER(LANG(?showAs) = "en")
}
GROUP BY ?entity ?showAs
ORDER BY DESC(?frequency)

CQ-A-06 — Which elements have fine-grained mentions but no coarse-level reference (data gap)?

PREFIX ann: <https://w3id.org/ldso/annotations#>

SELECT DISTINCT ?element ?entity WHERE {
  ?element ann:hasMention ?m .
  ?m ann:mentionOf ?entity .
  FILTER NOT EXISTS { ?element ann:refersToEntity ?entity . }
}
# Expected result: empty set in a fully annotated corpus.

Conformance

A dataset conforms to LDSO-Annotations if, for every ann:EntityMention instance, all SHACL shapes in shapes.ttl pass without Violations. Warnings MAY be present and indicate recommended but not mandatory conditions.

A conformant producer MUST:

  • Assert ann:mentionOf, ann:inElement, and ann:surfaceForm on every ann:EntityMention.
  • Assert ann:endChar whenever ann:startChar is present, with ann:endChar strictly greater.
  • Restrict ann:confidence values to the range [0.0, 1.0].

A conformant producer SHOULD:

  • Also assert ann:refersToEntity on any element that carries fine-grained ann:hasMention assertions, for each canonical entity mentioned.
  • Ensure that each target of ann:refersToEntity is typed as ent:NamedEntity.
