LDSO — Legal Document Structure Ontology

A modular RDF/OWL vocabulary stack for legal document structure, entities, lifecycle, semantics, and operational rules

Overview

The Legal Document Structure Ontology (LDSO) is a layered family of RDF/OWL modules for representing legal documents in machine-readable form — from raw structural hierarchy through named entity annotation, legal lifecycle management, deontic semantic annotation, and operational rule execution.

The stack is designed for modular adoption: consume only the layers you need. A simple document indexer needs only LDSO-Core. A knowledge graph linking entities across a corpus adds LDSO-Entities and LDSO-Annotations. A compliance reasoning engine adds LDSO-Semantics and LDSO-Operations.

All modules share the base IRI https://w3id.org/ldso/, use Dublin Core Terms for metadata, SKOS for taxonomy, SHACL for data validation, and follow Semantic Versioning. Source code is at github.com/geoknoesis/ldso.

Modules

Layer 1

LDSO-Core

Prefix: ldso:  ·  https://w3id.org/ldso/core#

Generic RDF/OWL vocabulary for the structural hierarchy of legal documents: LegalResource, LegalExpression, Document, and 20+ element types (Chapter, Article, Paragraph, Item, Annex, Table, …). Covers ordering, citation paths, and the FRBR-inspired resource/expression identity model.

Spec ontology.ttl shapes.ttl
Layer 2b

LDSO-Entities

Prefix: ent:  ·  https://w3id.org/ldso/entities#

Named entity catalogue for legal documents. A single ent:NamedEntity class with SKOS-based type taxonomy (Person, Organization, Location, Concept, Role, Event, Process) and canonical URI linking via ent:href. Extensible by domain verticals without modifying this ontology.

Spec ontology.ttl shapes.ttl
Layer 2c

LDSO-Annotations

Prefix: ann:  ·  https://w3id.org/ldso/annotations#

Document annotation module linking structural elements to named entities. Supports coarse annotation (ann:refersToEntity) and fine-grained NER output (ann:EntityMention) with surface forms, character offsets, and confidence scores.

Spec ontology.ttl shapes.ttl
Layer 3

LDSO-Lifecycle

Prefix: life:  ·  https://w3id.org/ldso/lifecycle#

Legal document lifecycle and amendment ontology. Models lifecycle events (Entry, Suspension, Repeal, Expiry), amendment instructions, amendment effects, version chains (life:supersedes), temporal applicability intervals, and consolidated text provenance.

Spec ontology.ttl shapes.ttl
Layer 4

LDSO-Semantics

Prefix: leg:  ·  https://w3id.org/ldso/semantics#

Legal semantic annotation ontology. Provides first-class RDF nodes for deontic norms — Obligation, Permission, Prohibition, Right, Discretion — plus definitional content (Definition), scoping (Scope), and conditionality (Condition, Exception, Exemption). Linked to structure via leg:annotates.

Spec ontology.ttl shapes.ttl
Layer 5

LDSO-Operations

Prefix: ops:  ·  https://w3id.org/ldso/operations#

Operational rule layer. Bridges deontic semantics to machine-executable rules. Defines OperativeRule, five Trigger subtypes, five Criterion subtypes, Procedure + ordered Steps, three Schedule types, Measurement with Comparators, and DocumentaryRequirement. Domain-agnostic — designed for extension by trade, environmental, and financial verticals.

Spec ontology.ttl shapes.ttl

Layer Stack

LDSO is organized in layers. Each module is self-contained and imports only the layers below it. Domain vertical ontologies (trade, environment, finance) extend Layer 5 without modifying core LDSO modules.

Layer 6 Evaluation — rule results, compliance scores
Layer 5b Domain Verticals — Trade Agreement Ontology, Environment, Finance, …
Layer 5 LDSO-Operations — operative rules, triggers, criteria, procedures
Layer 4 LDSO-Semantics — obligations, permissions, definitions, conditions
Layer 3 LDSO-Lifecycle — amendments, versions, consolidation
Layer 2c LDSO-Annotations — entity mentions, surface forms, NER output
Layer 2b LDSO-Entities — named entity catalogue
Layer 1 LDSO-Core — document structure, LegalResource/LegalExpression

Quick Start

The following Turtle snippet shows a minimal LDSO instance covering all six layers: a legal resource with one document expression, an entity catalogue entry, an entity mention annotation, a lifecycle event, a deontic obligation, and one operative rule. 

@prefix ldso: <https://w3id.org/ldso/core#> .
@prefix ent:  <https://w3id.org/ldso/entities#> .
@prefix ann:  <https://w3id.org/ldso/annotations#> .
@prefix life: <https://w3id.org/ldso/lifecycle#> .
@prefix leg:  <https://w3id.org/ldso/semantics#> .
@prefix ops:  <https://w3id.org/ldso/operations#> .
@prefix dct:  <http://purl.org/dc/terms/> .
@prefix skos: <http://www.w3.org/2004/02/skos/core#> .
@prefix ex:   <https://example.org/ata/> .

# ── Layer 1: Document Structure ────────────────────────────────────────────
ex:ata
  a ldso:LegalResource ;
  dct:title "ATA Convention"@en ;
  ldso:hasExpression ex:ata_en .

ex:ata_en
  a ldso:Document ;
  dct:language "en" ;
  dct:issued "1961-12-06"^^xsd:date ;
  ldso:expressionOf ex:ata ;
  ldso:contains ex:art_1 .

ex:art_1
  a ldso:Article ;
  ldso:notation "1" ;
  ldso:citation "Article 1" ;
  ldso:text "For the purposes of this Convention, the term..."@en .

# ── Layer 2b: Named Entity Catalogue ───────────────────────────────────────
ex:wco
  a ent:NamedEntity ;
  ent:entityType ent:Organization ;
  ent:showAs "World Customs Organization"@en, "Organisation mondiale des douanes"@fr ;
  ent:href <https://www.wikidata.org/entity/Q186049> .

# ── Layer 2c: Entity Annotation ────────────────────────────────────────────
ex:art_1 ann:refersToEntity ex:wco .

ex:m1
  a ann:EntityMention ;
  ann:mentionOf   ex:wco ;
  ann:inElement   ex:art_1 ;
  ann:surfaceForm "World Customs Organization"@en ;
  ann:startChar   23 ;
  ann:endChar     51 ;
  ann:confidence  0.98 .

# ── Layer 3: Lifecycle ──────────────────────────────────────────────────────
ex:entry_1961
  a life:Entry ;
  life:affects  ex:ata_en ;
  life:eventDate "1963-07-30"^^xsd:date .

ex:ata_en life:validFrom "1963-07-30"^^xsd:date .

# ── Layer 4: Legal Semantics ────────────────────────────────────────────────
ex:oblig_present_carnet
  a leg:Obligation ;
  leg:annotates ex:art_1 ;
  rdfs:label "Obligation to present carnet"@en .

# ── Layer 5: Operative Rule ─────────────────────────────────────────────────
ex:rule_ta
  a ops:OperativeRule ;
  ops:operativizes ex:oblig_present_carnet ;
  ops:hasTrigger   ex:trig_carnet ;
  rdfs:label "Rule: Temporary Admission — Carnet Presentation"@en .

ex:trig_carnet
  a ops:DocumentTrigger ;
  rdfs:label "ATA Carnet presented at customs"@en .

Import Statement

To import the full stack in a single OWL ontology:

<https://example.org/my-ontology>
  a owl:Ontology ;
  owl:imports <https://w3id.org/ldso/core>,
              <https://w3id.org/ldso/entities>,
              <https://w3id.org/ldso/annotations>,
              <https://w3id.org/ldso/lifecycle>,
              <https://w3id.org/ldso/semantics>,
              <https://w3id.org/ldso/operations> .

Design Principles

  1. Strict layer separation. Structure, semantics, lifecycle, and operational rules are represented in separate modules. No module mixes concerns from another layer.
  2. DC Terms for metadata. All document-level metadata uses Dublin Core Terms (dct:title, dct:language, dct:issued, dct:format). No custom LDSO metadata properties.
  3. SKOS for taxonomies. Entity type classification uses a SKOS ConceptScheme — not OWL subclasses — enabling multi-dimensional typing and domain extension without modifying core modules.
  4. SHACL for validation. Every module ships a companion shapes.ttl with SHACL NodeShapes, property constraints, and SPARQL-based integrity checks.
  5. IRI-first identity. Every meaningful resource is identified by an IRI. Blank nodes are not used for primary entities.
  6. Modular adoption. Each module can be deployed independently. A system consuming only Layer 1 has no dependency on Layers 2–5.

Contributing

The LDSO project is maintained at github.com/geoknoesis/ldso. Bug reports, feature requests, and pull requests are welcome via the issue tracker.

When contributing ontology terms, follow the quality requirements in LDSO-Core §3: every class and property must have an IRI, rdfs:label, skos:definition, skos:scopeNote, skos:example, and rdfs:isDefinedBy.
