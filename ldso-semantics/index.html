LDSO-Semantics is an RDF/OWL ontology module that provides a vocabulary for annotating the deontic and definitional content of legal provisions. It records what provisions oblige, permit, prohibit, entitle, define, and scope — without encoding structural form (LDSO-Core) or lifecycle state (LDSO-Lifecycle). Annotations are first-class nodes that point to structural elements via leg:annotates, keeping structure and meaning cleanly separated. LDSO-Semantics is part of the Legal Document Structure Ontology (LDSO) family and extends LDSO-Core.

Introduction

Legal provisions have both a structural form and a normative meaning. A paragraph may be a structural unit in the sense of LDSO-Core; but it may also oblige an entity to do something, permit a course of action, prohibit a practice, or define a term. These are distinct levels of description that benefit from being separately recorded and separately queried.

LDSO-Semantics provides the vocabulary for the semantic layer. Its central concept is the legal annotation: a first-class RDF node that captures the deontic or definitional meaning of a provision and is linked to the provision's structural node via leg:annotates. This design means:

  • the same provision may carry multiple annotations of different types (e.g., an obligation and a definition in the same article);
  • semantic annotations may be loaded as a separate named graph without altering the structural graph;
  • SPARQL queries can target structure, meaning, or both independently.

Scope and Out of Scope

LDSO-Semantics is scoped to semantic annotation of legal provisions.

The following are out of scope and belong in other modules:

  • Document structure, element hierarchy, citations — see LDSO-Core.
  • Named entities (persons, organizations, roles, concepts) — see LDSO-Entities.
  • Amendments, versions, consolidation — see LDSO-Lifecycle.
  • Operational trade rules, HS triggers, tariff rates — see domain ontologies.
  • Compliance evaluation and execution results — see evaluation ontologies.

Design Principles

  1. Structure is independent from meaning. ldso:Article is a structural class. leg:Obligation annotates that article. The two are linked by leg:annotates in one direction only (annotation → element), never the reverse.
  2. Annotations are first-class nodes. Legal annotations have their own IRIs and carry their own properties. They are not blank nodes or property bags attached to structural elements. This enables annotations to be versioned, queried, and loaded independently.
  3. Deontic type is carried by the subclass. The distinction between an obligation, permission, and prohibition is modelled as an OWL class — not as a property value. SPARQL patterns over ?x a leg:Obligation are more efficient and compositional than filtering on string values.
  4. Modal evidence is preserved verbatim. The modal verb or construction from the source text (e.g., shall, may not, is entitled to) is captured in leg:deonticModal as a plain string. This supports corpus linguistics, compliance review, and NLP pipelines without losing the original linguistic evidence.
  5. Inverse properties are asserted explicitly. Both directions of the condition pair (leg:conditionedBy / leg:conditionOf) and the exception pair (leg:exceptedBy / leg:exceptionOf) MUST be asserted in data. Relying solely on OWL inference for inverse triples causes fragile SPARQL results in RDF engines that do not perform forward-chaining.
  6. Conditions are reusable standalone nodes. A leg:Condition is not itself a leg:LegalAnnotation. It is a separate node that may be referenced by multiple NormativeStatements — supporting shared preconditions without duplication.
  7. Layered modeling. Structural concerns (LDSO-Core), semantic annotations (this module), lifecycle and effect (LDSO-Lifecycle), and domain rules are kept in separate ontology layers linked by reference, not merged.

Annotation Model

The central pattern of LDSO-Semantics is: 

annotation ──leg:annotates──> structural_element

A leg:LegalAnnotation is a separate resource from the structural element it describes. The annotation does not modify or attach to the element; it merely points to it. This allows the same element to carry multiple annotations, and allows annotations to be queried, loaded, or removed without touching the structural graph.

Class Hierarchy

leg:LegalAnnotation
├── leg:NormativeStatement
│   ├── leg:Obligation      (SHALL / MUST)
│   ├── leg:Permission      (MAY / IS PERMITTED TO)
│   ├── leg:Prohibition     (SHALL NOT / MUST NOT)
│   ├── leg:Right           (IS ENTITLED TO / HAS THE RIGHT TO)
│   └── leg:Discretion      (MAY AT ITS DISCRETION)
├── leg:Definition          (defined term + definition text)
├── leg:Exception           (carve-out from a norm)
│   └── leg:Exemption       (named-subject exception)
└── leg:Scope               (range of applicability)

leg:Condition               (standalone prerequisite — NOT a LegalAnnotation)

Core Pattern

Every legal annotation MUST carry at least one leg:annotates triple pointing to the source structural element. The following example shows an obligation linked to a paragraph: 

ex:Oblig_Para1_Admit
    a leg:Obligation ;
    leg:annotates          ex:para_1 ;
    leg:normativeSubject   ex:contracting_party ;
    leg:normativeObject    ex:goods ;
    leg:deonticModal       "shall" ;
    leg:normativeText      """Goods shall be admitted temporarily into the customs
territory of a Contracting Party without payment of import duties and
taxes, provided that they are intended for re-exportation."""@en ;
    leg:conditionedBy      ex:Cond_ReExport ;
    leg:hasScopeAnnotation ex:Scope_Art2_5 .

The structural element ex:para_1 is declared in the LDSO-Core graph. The annotation ex:Oblig_Para1_Admit may reside in a separate named graph. Neither graph is modified by the other.

Conformance

A conforming LDSO-Semantics implementation MUST:

  1. Use the namespace https://w3id.org/ldso/semantics# for all LDSO-Semantics terms.
  2. Type every legal annotation node as the appropriate subclass of leg:LegalAnnotation — one of leg:Obligation, leg:Permission, leg:Prohibition, leg:Right, leg:Discretion, leg:Definition, leg:Condition, leg:Exception, leg:Exemption, or leg:Scope.
  3. Link every legal annotation to its source document element via leg:annotates.
  4. Ensure that leg:Condition and leg:Exception nodes are linked to their target annotation via leg:conditionFor or leg:exceptionTo respectively.
  5. Not embed obligation/permission/prohibition logic inside LDSO-Core structural nodes — legal semantics MUST be represented as separate first-class nodes.
  6. Pass all SHACL shapes defined in shapes.ttl without violations.

A conforming implementation SHOULD:

  • Link definitional annotations (leg:Definition) to the entity being defined via leg:defines.
  • Record the legal provision in which an annotation is stated via leg:statedIn.

Normative Statements

A leg:NormativeStatement is a legal annotation that records a deontic norm expressed in a provision. All normative statements MUST carry leg:annotates and leg:deonticModal. They SHOULD also carry leg:normativeSubject identifying who bears the norm.

leg:Obligation

IRI: https://w3id.org/ldso/semantics#Obligation

SubclassOf: leg:NormativeStatement

Definition: A normative statement imposing a duty on the normative subject to perform or refrain from a specific act. Expressed in legal text by SHALL, MUST, IS REQUIRED TO, IS OBLIGED TO, or equivalent.

Required properties: leg:annotates (MUST), leg:deonticModal (MUST), leg:normativeSubject (SHOULD), leg:normativeObject (SHOULD)

ex:Oblig_Para3_Grant
    a leg:Obligation ;
    leg:annotates        ex:para_3 ;
    leg:normativeSubject ex:competent_authority ;
    leg:normativeObject  ex:temporary_admission ;
    leg:deonticModal     "shall" ;
    leg:normativeText    """Where the competent authority is satisfied that the
conditions set out in paragraphs 1 and 2 are fulfilled, it shall grant
temporary admission."""@en ;
    leg:conditionedBy    ex:Cond_SatisfiedConditions .

leg:Permission

IRI: https://w3id.org/ldso/semantics#Permission

SubclassOf: leg:NormativeStatement

Definition: A normative statement conferring on the normative subject a faculty to perform an act that would otherwise be restricted or uncertain. Expressed in legal text by MAY, IS PERMITTED TO, IS AUTHORIZED TO, or equivalent.

Usage note: Distinguish from leg:Discretion (an explicit operational power to an institutional actor) and from leg:Right (an enforceable entitlement against a duty-bearer). A Permission removes or relaxes a presumed restriction.

ex:Perm_VoluntaryDeclaration
    a leg:Permission ;
    leg:annotates        ex:art_6 ;
    leg:normativeSubject ex:applicant ;
    leg:deonticModal     "may" ;
    leg:normativeText    "An applicant may file a voluntary declaration
in lieu of an ATA carnet."@en .

leg:Prohibition

IRI: https://w3id.org/ldso/semantics#Prohibition

SubclassOf: leg:NormativeStatement

Definition: A normative statement forbidding the normative subject from performing a specific act. Expressed in legal text by SHALL NOT, MUST NOT, IS PROHIBITED FROM, MAY NOT, or equivalent.

Usage note: A Prohibition is an explicit legal barrier, not merely the absence of a Permission. No Party shall impose any form of export price requirement.

ex:Prohib_ExportPriceReq
    a leg:Prohibition ;
    leg:annotates        ex:art_8 ;
    leg:normativeSubject ex:contracting_party ;
    leg:deonticModal     "shall not" ;
    leg:normativeText    "No Contracting Party shall impose any form of export
price requirement for goods admitted temporarily."@en .

leg:Right

IRI: https://w3id.org/ldso/semantics#Right

SubclassOf: leg:NormativeStatement

Definition: A normative statement conferring on the normative subject a legal entitlement against one or more duty-bearers. A Right correlates with a corresponding Obligation on another party. Expressed by IS ENTITLED TO, HAS THE RIGHT TO, SHALL BE ENTITLED TO, or equivalent.

Usage note: Link the correlating Obligation on the duty-bearer via leg:correlatesTo when that obligation is separately annotated (Hohfeldian correlate structure).

ex:Right_Appeal
    a leg:Right ;
    leg:annotates      ex:art_11 ;
    leg:normativeSubject ex:applicant ;
    leg:deonticModal   "is entitled to" ;
    leg:normativeText  "The applicant is entitled to appeal any decision of
the competent authority within 30 days."@en ;
    leg:correlatesTo   ex:Oblig_ProcessAppeal .

leg:Discretion

IRI: https://w3id.org/ldso/semantics#Discretion

SubclassOf: leg:NormativeStatement

Definition: A normative statement conferring on the normative subject an operational power to take action at its own judgment. Expressed by MAY AT ITS DISCRETION, MAY DETERMINE, IS EMPOWERED TO, or equivalent.

Usage note: A Discretion grants a positive operational capability — typically to an administrative or institutional actor such as a competent authority or customs administration. It differs from a Permission (which removes a restriction) and a Right (which is an entitlement against a duty-bearer).

ex:Discr_ExtendPeriod
    a leg:Discretion ;
    leg:annotates        ex:art_5 ;
    leg:normativeSubject ex:competent_authority ;
    leg:normativeObject  ex:temporary_admission ;
    leg:deonticModal     "may" ;
    leg:normativeText    "The competent authority may extend the period of
temporary admission beyond the period initially fixed."@en .

Definitions

leg:Definition

IRI: https://w3id.org/ldso/semantics#Definition

SubclassOf: leg:LegalAnnotation

Definition: A legal annotation recording a term formally defined within a provision. The definition specifies the meaning of a named concept for the purposes of the legal instrument. A Definition carries the term itself (leg:definedTerm) and the definition text (leg:definitionText).

Required properties: leg:annotates (MUST), leg:definedTerm (MUST, language-tagged), leg:definitionText (MUST, language-tagged)

Optional properties: leg:definesEntity (links to an ent:NamedEntity in LDSO-Entities)

ex:Def_TemporaryAdmission
    a leg:Definition ;
    leg:annotates      ex:art_1 ;
    leg:definedTerm    "temporary admission"@en ;
    leg:definedTerm    "admission temporaire"@fr ;
    leg:definitionText """The customs procedure under which certain goods can be
brought into a customs territory conditionally relieved from payment of
import duties and taxes, provided such goods are imported for a specific
purpose and are intended for re-exportation within a specified period
without having undergone any change except normal depreciation due to the
use made of them."""@en ;
    leg:definesEntity  ex:temporary_admission .

Multiple definitions in one article SHOULD each be captured as a separate Definition instance. Where the official text exists in multiple languages, each language version of the term and text SHOULD be added as a separate language-tagged literal.

Conditions and Exceptions

Conditions vs. Exceptions

These two concepts are easily confused:

Condition (leg:Condition)
Restricts when a norm applies. It is the 'if' in an if-then normative structure. When a condition is not satisfied, the norm simply does not engage. Conditions are linked to norms via leg:conditionedBy.
Exception (leg:Exception)
Carves out categories, circumstances, or named subjects from a norm that would otherwise apply. The norm applies generally, but not to the excepted cases. Exceptions are linked to norms via leg:exceptedBy.

leg:Condition

IRI: https://w3id.org/ldso/semantics#Condition

Note: leg:Condition is not a subclass of leg:LegalAnnotation. It is a standalone reusable node that may be shared by multiple NormativeStatements via leg:conditionedBy.

Required properties: leg:conditionText (MUST, language-tagged)

Optional properties: leg:statedIn (the structural element stating the condition, when different from the element carrying the annotated norm), leg:conditionOf (inverse of leg:conditionedBy, MUST be asserted)

ex:Cond_ReExport
    a leg:Condition ;
    leg:conditionText  """The goods are intended for re-exportation within the
period specified in Article 7 without having undergone any change except
normal depreciation due to use."""@en ;
    leg:statedIn       ex:para_1 ;
    leg:conditionOf    ex:Oblig_Para1_Admit .      # inverse — MUST be asserted

ex:Oblig_Para1_Admit
    leg:conditionedBy  ex:Cond_ReExport .         # forward — MUST be asserted

A single Condition may be referenced by multiple NormativeStatements — for example, a re-exportation requirement that governs both an obligation and a discretion in different paragraphs.

leg:Exception

IRI: https://w3id.org/ldso/semantics#Exception

SubclassOf: leg:LegalAnnotation

Definition: A legal annotation recording a carve-out from the general rule expressed by a NormativeStatement. An Exception specifies circumstances, categories, or cases to which the norm does not apply.

Required properties: leg:annotates (MUST), leg:exceptionOf (SHOULD, pointing to the NormativeStatement being excepted)

Inverse consistency: If A leg:exceptedBy B, then B leg:exceptionOf A MUST also be asserted. Both directions are required in data; do not rely on OWL inference alone.

ex:Exc_TransitGoods
    a leg:Exception ;
    leg:annotates    ex:para_2 ;
    leg:exceptionOf  ex:Oblig_Para2_Present ;       # forward — MUST be asserted
    leg:exceptionText """Goods in transit through a customs territory under
customs supervision are not subject to the presentation requirement
of paragraph 2."""@en .

ex:Oblig_Para2_Present
    leg:exceptedBy   ex:Exc_TransitGoods .         # inverse — MUST be asserted

leg:Exemption

IRI: https://w3id.org/ldso/semantics#Exemption

SubclassOf: leg:Exception

Definition: A specific exception that releases a named subject, category, or item from a norm that would otherwise bind it. An Exemption names who or what is exempt, not merely the circumstances of inapplicability.

Usage note: Use when the legal text says 'X is exempt from Y', 'Y shall not apply to X', or 'X is excluded from the scope of this Article'.

ex:Exemp_DiplomaticGoods
    a leg:Exemption ;
    leg:annotates    ex:art_3 ;
    leg:exceptionOf  ex:Oblig_Para1_Admit ;
    leg:exceptionText "Goods carried for diplomatic purposes are exempt
from the temporary admission documentation requirements."@en .

Scope Annotations

leg:Scope

IRI: https://w3id.org/ldso/semantics#Scope

SubclassOf: leg:LegalAnnotation

Definition: A legal annotation describing the range of subjects, objects, or situations to which a provision or group of provisions applies.

Required properties: leg:annotates (MUST), leg:scopeText (SHOULD, language-tagged)

Optional properties: leg:scopeOf (points to specific LegalAnnotations within the scope; inverse of leg:hasScopeAnnotation)

A Scope annotation may capture personal scope (who is bound), material scope (what activities or goods), territorial scope (which jurisdictions), and temporal scope (when the provision applies). 

ex:Scope_Art2_5
    a leg:Scope ;
    leg:annotates  ex:art_5 ;
    leg:scopeText  """Applies to each Contracting Party with respect to the
temporary admission of goods into its customs territory."""@en .

# Link individual norms to this scope
ex:Oblig_Para1_Admit
    leg:hasScopeAnnotation ex:Scope_Art2_5 .

ex:Oblig_Para2_Present
    leg:hasScopeAnnotation ex:Scope_Art2_5 .

Object Properties

PropertyDomainRangeDescription
leg:annotates leg:LegalAnnotation ldso:LegalElement Links a legal annotation to the structural element whose meaning it records. MUST be present on every LegalAnnotation.
leg:normativeSubject leg:NormativeStatement any The entity, role, or category of persons who bear the obligation, enjoy the permission, or hold the right. Typically an ent:Role or ent:Organization.
leg:normativeObject leg:NormativeStatement any The matter, action, thing, or situation the norm concerns — what is to be done, permitted, or forbidden.
leg:conditionedBy leg:NormativeStatement leg:Condition Links a NormativeStatement to a prerequisite Condition. Inverse of leg:conditionOf. Both directions MUST be asserted.
leg:conditionOf leg:Condition leg:NormativeStatement Inverse of leg:conditionedBy. Relates a Condition to the NormativeStatements it governs.
leg:exceptedBy leg:NormativeStatement leg:Exception Links a NormativeStatement to an Exception that carves out cases where it does not apply. Inverse of leg:exceptionOf. Both directions MUST be asserted.
leg:exceptionOf leg:Exception leg:NormativeStatement Inverse of leg:exceptedBy. Relates an Exception to the NormativeStatement from which it creates a carve-out.
leg:scopeOf leg:Scope leg:LegalAnnotation Relates a Scope annotation to the LegalAnnotation(s) whose applicability it delimits. Inverse of leg:hasScopeAnnotation.
leg:hasScopeAnnotation leg:LegalAnnotation leg:Scope Inverse of leg:scopeOf. Links a legal annotation to a Scope that delimits its applicability.
leg:statedIn leg:Condition / leg:Exception ldso:LegalElement Links a Condition or Exception to the structural element where it is textually stated, when that element differs from the element carrying the annotated norm.
leg:correlatesTo leg:Right leg:Obligation Relates a Right to its Hohfeldian correlate Obligation on the duty-bearer. Use when both annotations are separately declared.
leg:definesEntity leg:Definition ent:NamedEntity Links a Definition to the named entity (from LDSO-Entities) that represents the concept being defined.

Datatype Properties

PropertyDomainRangeDescription
leg:deonticModal leg:NormativeStatement xsd:string The modal verb or construction from the source text preserved verbatim (e.g., "shall", "may not", "is entitled to"). MUST be present on every NormativeStatement.
leg:normativeText leg:NormativeStatement rdf:langString The verbatim normative sentence from the source provision, language-tagged. Capture the minimal self-contained sentence expressing the norm.
leg:definedTerm leg:Definition rdf:langString The term being defined, exactly as it appears in the definition clause, language-tagged. MUST be present. Multiple language tags are permitted.
leg:definitionText leg:Definition rdf:langString The verbatim text of the definition as it appears in the legal instrument, language-tagged. MUST be present.
leg:conditionText leg:Condition rdf:langString The natural-language formulation of the condition, language-tagged. May be a direct quotation or a minimal paraphrase. MUST be present.
leg:scopeText leg:Scope rdf:langString A natural-language description of the scope, language-tagged. SHOULD be present.
leg:exceptionText leg:Exception rdf:langString The verbatim or paraphrased text of the exception, language-tagged.

SHACL Validation

The file shapes.ttl provides SHACL shapes validating the constraints summarised below. Run validation with: 

pyshacl -s shapes.ttl -sf turtle -df turtle examples/example.ttl
ShapeTargetValidatesSeverity
leg:LegalAnnotationShape leg:LegalAnnotation leg:annotates minCount 1, class ldso:LegalElement Violation
leg:NormativeStatementShape leg:NormativeStatement leg:deonticModal present (xsd:string); leg:normativeSubject present Violation / Warning
leg:ObligationShape leg:Obligation Modal matches obligatory pattern (shall, must, is required to, is obliged to) Warning
leg:PermissionShape leg:Permission Modal matches permissive pattern (may, is permitted to, is authorized to) Warning
leg:ProhibitionShape leg:Prohibition Modal matches prohibitive pattern (shall not, must not, is prohibited from, may not) Warning
leg:DefinitionShape leg:Definition leg:definedTerm (rdf:langString, minCount 1); leg:definitionText (rdf:langString, minCount 1) Violation
leg:ExceptionShape leg:Exception leg:exceptionOf pointing to a NormativeStatement Warning
leg:ConditionShape leg:Condition leg:conditionText (rdf:langString, minCount 1) Violation
leg:ScopeShape leg:Scope leg:scopeText (rdf:langString, minCount 1) Warning
leg:ExceptionInverseShape subjects of leg:exceptedBy If A leg:exceptedBy B, then B MUST have leg:exceptionOf A Violation
leg:ConditionInverseShape subjects of leg:conditionedBy If A leg:conditionedBy B, then B MUST have leg:conditionOf A Violation

Example shape (inverse consistency check):

leg:ExceptionInverseShape
    a sh:NodeShape ;
    sh:targetSubjectsOf leg:exceptedBy ;
    sh:sparql [
        a sh:SPARQLConstraint ;
        sh:message "Exception chain broken: if A leg:exceptedBy B, then B must have leg:exceptionOf A." ;
        sh:select """
            PREFIX leg: <https://w3id.org/ldso/semantics#>
            SELECT $this ?exc WHERE {
                $this leg:exceptedBy ?exc .
                FILTER NOT EXISTS { ?exc leg:exceptionOf $this }
            }
        """ ;
    ] .

Usage Example

The following example annotates Article 2.5 of the Agreement on Temporary Admission (ATA Convention). It demonstrates obligations with conditions, an exception, a discretion, a definition linked to an entity, and a scope annotation. The full example is in examples/example.ttl.

Definition (Article 1)

ex:Def_TemporaryAdmission
    a leg:Definition ;
    rdfs:label         "Definition of temporary admission"@en ;
    leg:annotates      ex:art_1 ;
    leg:definedTerm    "temporary admission"@en ;
    leg:definedTerm    "admission temporaire"@fr ;
    leg:definitionText """The customs procedure under which certain goods can be
brought into a customs territory conditionally relieved from payment of
import duties and taxes, provided such goods are imported for a specific
purpose and are intended for re-exportation within a specified period
without having undergone any change except normal depreciation due to the
use made of them."""@en ;
    leg:definesEntity  ex:temporary_admission .  # links to ent:Concept

Obligation with Condition (Paragraph 1)

# Condition (reusable standalone node)
ex:Cond_ReExport
    a leg:Condition ;
    rdfs:label        "Condition: goods intended for re-exportation"@en ;
    leg:conditionText """The goods are intended for re-exportation within the period
specified in Article 7 without having undergone any change except normal
depreciation due to use."""@en ;
    leg:statedIn      ex:para_1 ;
    leg:conditionOf   ex:Oblig_Para1_Admit .    # inverse — MUST be asserted

# Obligation
ex:Oblig_Para1_Admit
    a leg:Obligation ;
    rdfs:label         "Obligation: admit goods temporarily (para 1)"@en ;
    leg:annotates      ex:para_1 ;
    leg:normativeSubject ex:contracting_party ;
    leg:normativeObject  ex:goods ;
    leg:deonticModal   "shall" ;
    leg:normativeText  """Goods shall be admitted temporarily into the customs territory
of a Contracting Party without payment of import duties and taxes, provided
that they are intended for re-exportation within the period specified in
Article 7."""@en ;
    leg:conditionedBy  ex:Cond_ReExport ;        # forward — MUST be asserted
    leg:hasScopeAnnotation ex:Scope_Art2_5 .

Obligation with Exception (Paragraph 2)

ex:Oblig_Para2_Present
    a leg:Obligation ;
    rdfs:label         "Obligation: present admission document (para 2)"@en ;
    leg:annotates      ex:para_2 ;
    leg:normativeSubject ex:applicant ;
    leg:normativeObject  ex:ata_carnet ;
    leg:deonticModal   "shall" ;
    leg:normativeText  """The applicant for temporary admission shall present to the
competent authority one of the following documents: (a) an ATA carnet;
(b) a national customs document; (c) a declaration in accordance with Article 6."""@en ;
    leg:hasScopeAnnotation ex:Scope_Art2_5 ;
    leg:exceptedBy     ex:Exc_TransitGoods .     # inverse — MUST be asserted

ex:Exc_TransitGoods
    a leg:Exception ;
    rdfs:label      "Exception: transit goods exempt from documentation requirement"@en ;
    leg:annotates   ex:para_2 ;
    leg:exceptionOf ex:Oblig_Para2_Present ;     # forward — MUST be asserted
    leg:exceptionText """Goods in transit through a customs territory under customs
supervision are not subject to the presentation requirement of paragraph 2."""@en .

Discretion (Article 5)

ex:Discr_ExtendPeriod
    a leg:Discretion ;
    rdfs:label         "Discretion: extend temporary admission period"@en ;
    leg:annotates      ex:art_5 ;
    leg:normativeSubject ex:competent_authority ;
    leg:normativeObject  ex:temporary_admission ;
    leg:deonticModal   "may" ;
    leg:normativeText  """The competent authority may extend the period of temporary
admission beyond the period initially fixed."""@en .

Scope (Article 5 header)

ex:Scope_Art2_5
    a leg:Scope ;
    rdfs:label    "Scope of Article 2.5 — Admission Procedures"@en ;
    leg:annotates ex:art_5 ;
    leg:scopeText """Applies to each Contracting Party with respect to the temporary
admission of goods into its customs territory."""@en .

Competency Questions

The following questions define what LDSO-Semantics is designed to answer. Each is accompanied by a SPARQL query against a conformant dataset.

CQ-S-01 — What normative statements annotate a specific provision?

PREFIX leg: <https://w3id.org/ldso/semantics#>

SELECT ?annotation ?type ?modal WHERE {
  ?annotation leg:annotates <https://example.org/ata/para_1> ;
              a ?type .
  OPTIONAL { ?annotation leg:deonticModal ?modal }
  FILTER(STRSTARTS(STR(?type), "https://w3id.org/ldso/semantics#"))
  FILTER(?type != leg:LegalAnnotation)
}

CQ-S-05 — What norms apply to a specific normative subject?

PREFIX leg: <https://w3id.org/ldso/semantics#>

SELECT ?norm ?type ?modal ?element WHERE {
  ?norm leg:normativeSubject <https://example.org/ata/competent_authority> ;
        a ?type ;
        leg:annotates ?element .
  OPTIONAL { ?norm leg:deonticModal ?modal }
  FILTER(STRSTARTS(STR(?type), "https://w3id.org/ldso/semantics#"))
  FILTER(?type != leg:LegalAnnotation)
  FILTER(?type != leg:NormativeStatement)
}
ORDER BY ?element

CQ-S-09 — What exceptions qualify a specific obligation?

PREFIX leg: <https://w3id.org/ldso/semantics#>

SELECT ?exception ?exceptionText WHERE {
  <https://example.org/ata/Oblig_Para2_Present>
    leg:exceptedBy ?exception .
  OPTIONAL { ?exception leg:exceptionText ?exceptionText }
}

CQ-S-11 — What terms are defined in the document?

PREFIX leg: <https://w3id.org/ldso/semantics#>

SELECT ?definition ?term ?definitionText WHERE {
  ?definition a leg:Definition ;
              leg:definedTerm ?term ;
              leg:definitionText ?definitionText .
  FILTER(LANG(?term) = "en")
}
ORDER BY ?term

CQ-S-20 — Integrity check: are there broken exception inverse chains?

PREFIX leg: <https://w3id.org/ldso/semantics#>

SELECT ?norm ?exc WHERE {
  ?norm leg:exceptedBy ?exc .
  FILTER NOT EXISTS { ?exc leg:exceptionOf ?norm }
}
# Expected result: no rows.

CQ-S-25 — What conditions must be satisfied before an obligation becomes operative?

PREFIX leg: <https://w3id.org/ldso/semantics#>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>

SELECT ?obligation ?condition ?conditionText WHERE {
  ?obligation a leg:Obligation ;
              leg:conditionedBy ?condition .
  OPTIONAL { ?condition rdfs:label ?conditionText }
}
ORDER BY ?obligation

CQ-S-30 — What permissions apply within a given scope?

PREFIX leg: <https://w3id.org/ldso/semantics#>

SELECT ?permission ?element WHERE {
  ?scope a leg:Scope ;
         leg:annotates <https://example.org/ata/chapter_2> .
  ?permission a leg:Permission ;
              leg:annotates ?element .
  <https://example.org/ata/chapter_2> ldso:contains+ ?element .
}
ORDER BY ?element
